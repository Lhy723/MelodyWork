# 功能对等矩阵与验收契约

关联：[总设计](./README.md) · [实施计划](./implementation-plan.md)。本文是实现与验收矩阵：核心 Pi 主链路已通过本地契约、单元、类型、架构和打包门禁；需要真实 provider、平台或第三方生态样本的行仍按状态标注，不能用本地通过替代现场验收。

## 1. 如何使用矩阵

证据等级：**A** = 已见桌面实现/类型/调用；**B** = vendored引擎文档或实现有能力，但需要核实桌面可达性与配置；**A+B** = 两侧均有证据。所有 B 项都必须在 P0 调查后明确纳入/不适用及理由；不得以“没有按钮”排除后台工具。

实现方式：**复用** = Pi公开能力并适配；**保留** = 原有宿主/产品实现；**补齐** = MelodyWork服务/受控工具/兼容层。核心行已有代码和自动化证据；真实模型、跨平台桌面和第三方生态行仍需按矩阵完成现场验收。

兼容原则：Pi 1.0.1 没有内置 MCP client，但 MelodyWork 已补齐 Host-owned 本地 stdio/HTTP/SSE、Web、基础 Memory、受控 LSP stdio、tree-sitter 代码库导航和受限 JSON command Hook bridge；Pi 扩展还接管两阶段 Memory Flush 与基础 `update_goal` 状态。旧 Melody/Claude JavaScript/HTTP hooks、未映射的 Stop 阻断语义、插件动态扩展、非 stdio/不受信任的 LSP、严格语义代码图、记忆 embedding/vector/dream、远端媒体生成和 headless OAuth 当前不能声称由 Pi 实现。Pi 只通过 Host 显式加载明确受控的 `.melody/skills` 与标准外部 `.agents/skills`、`.claude/skills`、`.cursor/skills` Markdown Skill，以及纯 Markdown 插件的 Skill/命令资源和受控命令根下的平面 Markdown prompt templates；不兼容的动态表面有明确诊断/阻断，不靠 ACP 静默回退。Pi 是唯一 Agent runtime；旧 ACP 会话只读归档。默认引擎为 Pi；Pi 连接前会静态检查配置和扩展，运行时不再切换引擎。Pi 原生入口与 Host 归属的详细说明见[原生能力对照](./native-alternatives.md)。

表中每个ID应落到测试报告，记录：基线操作、脱敏输入、旧引擎结果、Pi结果、平台/模型、代码版本、证据链接、负责人、状态（待调查/待实现/通过/阻塞）。性能与自然语言措辞不要求逐字相同，行为、权限、工具副作用和数据必须符合契约。

## 5. 生态兼容、记忆与媒体

终端工具补充：Pi 的 Host-owned `run_terminal_command` 已采用有界 stdout/stderr 读取；超过预览上限的输出会写入工作区内 `.melody/pi/tool-output/`，并返回可由 `workspace_read_tool_output` 分段读取的归档引用。MCP 结果超过 512 KiB 预览上限时使用 `mcp-output-*` 归档；归档目录拒绝符号链接，并限制单文件、文件数和总量。
